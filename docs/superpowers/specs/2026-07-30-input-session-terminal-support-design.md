# Input-session and terminal support design

## Purpose

TextMagic transforms text in the currently active Windows application by running user-editable PowerShell scripts. A script receives UTF-8 text through `stdin` and returns the replacement through `stdout`.

The application supports two input sources:

1. Explicitly selected text in an ordinary editable control.
2. The last physically typed word tracked by TextMagic.

Terminal support is intentionally limited to the second source. TextMagic must transform the current command-line word; it does not attempt to replace selected terminal output or terminal history.

## Problem

The current script flow probes selection first by sending `Ctrl+C`. In terminals this can interrupt the running command instead of copying text. Process-based terminal detection is incomplete and cannot distinguish the VS Code editor from its integrated terminal.

The previous-word path also depends on selection and clipboard paste during replacement. Terminal key bindings differ, so `Shift+Left` plus `Ctrl+V` is not a portable replacement mechanism.

## Goals

- Never send a copy shortcut when a current last-word input session is available.
- Make last-word transformation independent of terminal processes and key bindings.
- Preserve selected-text behavior when the user explicitly invalidates the typing session by selecting or moving the caret.
- Never modify text if the user changes the input context while a script is running.
- Keep the solution Windows-native and dependency-free.
- Document the actual product contract for users and future Codex sessions.

## Non-goals

- Detecting or maintaining a list of terminal applications.
- Replacing terminal scrollback or arbitrary selected terminal output.
- Supporting non-Windows platforms or additional script runtimes.
- Redesigning the existing custom widgets or context menus.

## Input-session model

`InputBuffer` remains the single owner of captured text. It gains the minimum context needed to determine whether its contents still describe the active input stream:

- the top-level foreground window that received the physical input;
- a monotonically increasing generation changed by append, backspace, clear, and replacement;
- the existing captured word, trailing separators, replacement offset, and expected buffer size.

A previous-word capture is current only when:

- its buffer contents and generation still match;
- the foreground window matches the captured window;
- no invalidating input event occurred.

No terminal classification is needed.

## Invalidation rules

The typing session is cleared when the user can reasonably have moved the caret, changed selection, or changed input context:

- physical mouse button input;
- Left, Right, Up, Down, Home, End, Page Up, Page Down, Insert, or Delete;
- selection commands such as `Ctrl+A` and navigation with Shift/Ctrl;
- switching to another foreground window;
- other non-script shortcuts that can change focus or document position.

Modifier keys and a registered TextMagic hotkey do not invalidate the session by themselves. Injected events generated by TextMagic remain ignored by the global hooks.

## Source selection

When a script hotkey is invoked:

1. Ask `InputBuffer` for a current previous-word capture bound to the active foreground window.
2. If available, use the captured word immediately and do not probe the clipboard.
3. Otherwise, retain the existing selected-text probe for ordinary controls.
4. If there is no selection, retain the configured all-text fallback behavior.

This ordering makes terminal behavior a consequence of a valid physical typing session rather than an application-specific exception. Mouse or keyboard selection invalidates the session first, so explicit selection still wins in ordinary applications.

UI-triggered script execution remains clipboard-only as currently implemented.

## Previous-word replacement

The source word is not removed before PowerShell completes.

After successful execution:

1. Revalidate the capture, foreground window, buffer generation, and expected tail.
2. If stale, leave the target application unchanged and report that the input context changed.
3. Delete exactly `word + trailing separators` with Backspace input.
4. Type `script output + trailing separators` using the existing Unicode `SendInput` path.
5. Commit the same replacement to `InputBuffer`.

This path uses neither clipboard copy nor terminal paste shortcuts and therefore applies equally to ordinary controls and terminal command lines.

## Failure handling

- Script failure leaves the target application untouched.
- A stale capture leaves the target application untouched.
- If deletion fails, do not type or commit anything.
- If typing fails after deletion, remove the number of replacement characters reported as typed and make a best-effort restoration of the original word and trailing separators.
- Commit the local buffer only after the target replacement succeeds.
- Log the failure and show the existing status/error UI; do not add new dialogs or UI systems.

The restoration is best-effort because a foreign application can reject injected input at any point. This limitation is preferable to silently claiming success.

## Testing

Extend the existing console-only `InputBufferTests` rather than adding a framework:

- captures are bound to the expected foreground-window identity;
- navigation and selection invalidation make a capture stale;
- input during script execution makes a capture stale;
- successful replacement preserves trailing separators without left drift;
- stale captures do not mutate the buffer;
- partial replacement bookkeeping supports best-effort restoration.

Run a fresh Debug build and the complete CTest suite.

Manual verification uses physical keystrokes because TextMagic intentionally ignores injected hook events:

1. Notepad: previous word, explicit mouse selection, `Ctrl+A`, and caret movement.
2. Windows Terminal with PowerShell and cmd: previous-word uppercase and layout conversion.
3. VS Code editor: previous word and explicit selection.
4. VS Code integrated terminal: previous-word uppercase and layout conversion.
5. Start a slow script, type or switch windows before completion, and verify that nothing is replaced.
